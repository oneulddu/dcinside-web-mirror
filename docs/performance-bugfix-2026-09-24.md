# 성능·버그 개선 (2026-09-24)

기준 커밋은 `9ee4c7e`다. Opus 주 에이전트가 수집기·캐시·라우트를 직접 읽고,
Astra 탐색자 두 명이 미디어·외부 링크 계열과 브라우저 스크립트를 나누어 조사했다.
채택한 일곱 항목은 Astra 작업자가 구현했고, 수정 전 실패하는 회귀 테스트로 먼저 재현했다.

## 검증

- Python 3.12 임시 가상환경에서 기준 테스트 700개 통과를 확인했다.
- 새 Python 회귀 테스트 16개 중 10개가 수정 전에 실패했다. 나머지는 유지해야 할 동작을 고정한다.
- JavaScript 회귀 테스트는 세 문제와 리뷰에서 나온 결합 부호 사례를 수정 전에 실패로 재현했다.
- 수정 후 전체 `pytest` 716개, `node --test tests/javascript/*.test.cjs` 9개 통과.
- 독립 Astra 코드 리뷰에서 결합 부호(`\p{M}`)를 지우면 모음 부호만 다른 아랍어 댓글이 합쳐지는
  회귀를 지적받아 반영했다. 그 외 차단 수준의 지적은 없었다.

실제 브라우저와 운영 트래픽에서는 측정하지 않았다. 데이터 마이그레이션은 없으며,
문제가 생기면 변경 커밋을 되돌리고 기존 절차로 재배포한다.

## 측정 후 보류한 항목

- 본문 HTML 가공 캐시: 본문 83KB, 이미지 80개, 댓글 400개인 모형 글에서 `/read` 렌더링이
  약 12ms였고 그중 본문 가공은 약 6ms였다. 캐시 무효화 위험에 비해 이득이 작아 추가하지 않았다.
- 미디어 본문 전체 시간 제한: 원본이 소켓 읽기 제한보다 짧은 간격으로 조금씩 보내면 요청 스레드를
  오래 점유할 수 있다. 허용 호스트가 DC 자체 CDN으로 한정되어 있고, 진행 중인 읽기를 끊으려면
  연결 강제 종료 장치가 필요해 이번 범위에서 제외했다.
- 댓글 0개 글의 PC 폴백: 원본 응답에서 "댓글 0개 확정"과 "개수 파싱 실패"를 구분할 근거가 없어 유지했다.
  이후 명시적 댓글 수와 미확인 값을 분리해 [댓글 0개 요청 절감](performance-zero-comments-2026-09-26.md)에 반영했다.
