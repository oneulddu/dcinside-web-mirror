# 전체 버그 검토와 수정

기준 커밋은 `9a76d3d`다. 캐시·비동기 처리, DC 수집기, 미디어·외부 링크,
라우트·최근 방문 쿠키, 브라우저 상태를 나누어 검토했다. 원본 응답과 시간을

## 검증

- Python 3.12 전체 테스트: `make test PYTHON=<python 경로>` — 551개 통과.
- 이후 방문 시각의 큰 정수 변환도 보완하고, 관련 쿠키 회귀 21개를 통과했다.
- 최종 리뷰가 찾은 빈 목록 이동 응답의 오판을 보완했다. 이동 스크립트가 있는
  빈 응답과 실제 빈 목록을 분리해 검증했으며, 수집기 관련 136개가 통과했다.
- JavaScript 상태 전이: `node --test tests/javascript/board_return_refresh.test.cjs` 통과.
- 변경 전 댓글 중복과 루프 준비 경쟁은 새 회귀 테스트가 실패하는 것을 확인했다.
- 새 테스트는 수집기 오판·본문 유실·댓글 중복, 쿠키 입력, 숫자 경계,
  인코딩 폴백과 시간 예산을 검증한다. 기존 미디어 SSRF·스트리밍 검사도 전체 실행에 포함했다.
- 브라우저에서는 실제 Flask 라우트·템플릿·JavaScript에 모형 수집 응답을 연결했다.
  검색어 `amp`, `lt`, `39`, `<`, `&` 각각에서 제목의 `textContent`가 원문과 같고
  제목 문자열의 태그가 DOM 요소로 실행되지 않는 것을 확인했다.
- Chromium의 bfcache를 켠 상태에서 글 클릭→뒤로→앞으로→뒤로를 실행했다.
  같은 문서의 식별값이 유지되고 목록 갱신 횟수가 1→2로 증가했다. 자동화 도구의
  기본 bfcache 비활성화 옵션만 해당 검증 세션에서 제외했으며 제품 설정은 바꾸지 않았다.
- 390px 화면에서 더보기 결과를 확인했다.

외부 사이트의 모든 응답과 운영 부하를 재현한 검토는 아니다. YouTube의 남은 시간
전달은 요청 시작·스트림 청크·폴백 사이에서 검사하며, 운영체제의 DNS나 블로킹 I/O를
강제로 중단하는 별도 타이머는 추가하지 않았다. 캐시 TTL·공개 API·데이터 저장 형식의
마이그레이션은 없으며, 문제가 발생하면 변경 커밋을 되돌리고 기존 배포 절차를 적용한다.

Opus 계획 검토는 Anthropic 인증 오류로 실행되지 않았다. 인증 설정은 변경하지 않았다.
별도 Astra 최종 코드 리뷰의 지적 1건을 반영했고, 재검토에서 추가 지적은 없었다.

## 추가 검토: 모바일 본문의 긴 URL

`b17f923`에서 실제 Flask `/read` 라우트에 모형 수집 응답을 연결해 재현했다.
공백 없는 긴 URL을 일반 문단, 링크, 표, `pre/code`, 인용·목록, 표 안의 코드에
넣고 일반 문장과 링크 미리보기도 함께 확인했다. 표는 `break-word`가 최소 너비
계산에 반영되지 않고, `pre`는 기본적으로 줄바꿈을 하지 않아 화면을 넓혔다.

- 본문의 `overflow-wrap`을 `anywhere`로 바꾸고 `pre`에 `white-space: pre-wrap`을
  적용했다. 원문과 링크 주소, 코드의 줄바꿈·들여쓰기를 보존한다.
- Chromium의 390px 창(스크롤바를 제외한 본문 뷰포트 375px)에서 페이지 너비가
  표는 4,423px, 코드는 9,860px로 늘어났다. 수정 후 둘 다 375px가 됐다.
- Chromium에서 320·360·390·430·1280px 너비 × 7가지 본문, WebKit의 iPhone 화면
  에뮬레이션에서 390px × 밝은/어두운 테마 × 7가지 본문을 확인했다. 총 49개
  조합에서 페이지와 본문에 가로 넘침이 없었다. 실제 iPhone 기기 검사는 아니다.
- 수정 전후 URL·링크 주소의 동일성과 코드 들여쓰기를 확인하고 화면도 검토했다.
- Python 3.12 전체 테스트: `make test PYTHON=<python 경로>` — 557개 통과.
