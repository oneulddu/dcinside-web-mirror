# UX Flow - 숨터 기본 화면 리디자인

## 최근 본 게시판 합치기와 게시글 시각 표기 (2026-09-26)

- 최근 본 게시판은 게시판(board + kind)마다 한 줄만 남긴다. 추천글 탭에서 방문해도 따로 저장하지 않고,
  링크는 항상 전체 목록(`recommend=0`)으로 연다. 예전 쿠키에 전체·추천글 두 줄이 있으면 읽을 때 가장 최근
  방문 한 줄로 합치고, 삭제는 그 게시판 기록을 한 번에 지운다. 쿠키·삭제 기록에서 `recommend` 값은 더 쓰지 않는다.
- 게시글 시각은 KST 달력 기준으로 표기한다. 목록·댓글·다른 글 행은 오늘 `14:05`, 어제 `어제 14:05`,
  올해 `9월 24일`, 그 전 `2025. 9. 24.`. 글 보기 머리는 `오늘 오후 2:05`, `9월 24일 오후 2:05`,
  `2025년 9월 24일 오후 2:05`처럼 시·분까지 보여 준다. 날짜만 아는 값(시간 보정 전 목록, 다른 글 행)은
  `어제`, `9월 24일`처럼 날짜만 쓰고 시각을 지어내지 않는다.
- `N분 전` 같은 상대 시간은 쓰지 않는다. 캐시된 목록이나 열어 둔 화면에서 금방 틀린 값이 되기 때문이다.
  캐시에는 원래 시각을 두고 화면을 그릴 때 `app/services/time_labels.py`로 문구를 만든다. 서버 렌더,
  `/read/related` JSON(`time`·`time_title`·`time_iso`), `/board/times` 시간 보정(`times`·`titles`·`datetimes`)이
  같은 함수를 쓴다. 모든 시각은 `<time datetime>`과 전체 날짜가 담긴 `title`을 가진다.
- 원본의 `HH:MM`·`MM.DD` 값에 날짜를 채울 때 서버 시간대 대신 KST 오늘을 기준으로 한다.

## 토스형 단색 리디자인 (2026-09-26)

- 사용자 승인 시안(`~/Downloads/숨터-홈-시안/최종/`)을 실제 화면에 적용했다. 원본 사이트 느낌을 빼기 위해
  갤러리→게시판, 흥한 갤러리→지금 뜨는 게시판, 개념글→추천글, 디시콘→이모티콘으로 사용자 문구를 바꿨다.
  URL 매개변수와 내부 이름(board, recommend, heung_q 등)은 그대로다.
- 전역 로고·부제·전체/베스트/최근 탭을 없앴다. 홈은 `베스트` 글자 링크(dcbest)와 `최근 본 게시판`
  타일(최근 방문 쿠키의 첫 8개, 이름 해석 순서는 `/recent`와 동일)로 대신한다. 게시판은 전체/추천글 탭,
  글 보기는 `< 게시판 이름` 뒤로 가기(원래 페이지·필터·refresh 유지)로 돌아간다.
- 기존 기능은 모두 유지한다: 홈 검색·초기화·결과 수·마이너/미니 표시·새 탭 이동·순위 페이지 이동·오류 문구,
  게시판 분류·검색 5범위·검색 해제·강조·읽은 글 흐리게·아이콘 5종·매니저 색·페이지 이동·시간 보정·복귀 갱신,
  글 보기 이미지/이모티콘 개별·전체 보기·링크 미리보기·임베드·답글·이모티콘 댓글·스팸 접기·다른 글 더보기·
  검색·목록으로·맨 위로, 최근 개별/전체 삭제, 이미지 차단 4단계 메뉴(키보드 ↑↓·Home·End·Esc).
- 게시판 머리의 검색 아이콘은 목록 아래 검색 입력으로 이동해 포커스한다(목록 교체 후에도 동작하도록 문서 위임).
- 글 보기 메타에 조회수를 추가했다(값이 없으면 생략). 홈 갱신 시각은 `오늘 오전 2:52 기준`,
  최근 방문 시각은 `오늘 04:12`/`어제`/`9월 24일` 형식이다. 게시글 시각 표기는 위 절을 따른다.
- 댓글 수는 대괄호 없이 숫자만 표시하고 `aria-label="댓글 N개"`를 붙인다. 분류는 대괄호 없이 표시한다.
  서버 템플릿과 `read_related_loader.js`가 같은 행 구조(`.feed-vote`, 구분점은 CSS)를 만든다.
- 검증: 320/390/768/1280px에서 네 화면 가로 넘침 없음, 양쪽 테마 스크린샷, 메뉴 키보드 조작,
  검색 아이콘 포커스, 게시판 검색 강조, 댓글 74개·답글 23개 글, 이미지 전체 차단 상태, 다른 글 더보기 추가 행,
  맨 위로 버튼, 콘솔 오류 없음. 파이썬 테스트 754개와 자바스크립트 테스트 9개 통과.
- 독립 리뷰 반영: 메타·읽은 글 글자 대비를 4.5:1 이상으로 올리고, 탭·분류의 누르는 영역을
  44px 이상으로 넓혔다. 원본에 조회수가 없으면 0 대신 표시를 생략한다.

## 홈 디자인 개선 (2026-09-19)

- 홈 검색, 순위 탐색, 이전/다음, 검색 초기화, 외부 갤러리 이동을 유지한다.
  기존 쿼리명·갤러리 종류·URL·데이터 조회 계약은 변경하지 않는다.
- 순위와 제목 시작선을 고정하고, 제목 아래 ID와 오른쪽 등급을 구분한다.
  모바일에서 갱신 시각은 제목 아래에 놓고 검색·헤더 컨트롤은 44px 이상으로 제공한다.
- 긴 이름/ID, 검색 결과, 결과 없음, 원본 조회 실패를 양쪽 테마에서 표시한다.
  외부 링크의 새 탭 안내와 `noopener`, 키보드 포커스, 테마 저장을 유지한다.
- Gemini 3.8 Flash가 실제 홈 스크린샷을 평가하고 주 에이전트가 수정·통합했다.
  이번 작업은 사용자가 지정한 평가 반복 방식이며 Opus/Fable 구현으로 기록하지 않는다.
- 완료 검증: 전체 테스트 683개, 320/390/768/1280px의 긴 내용·외부 검색·빈 결과·오류
  32개 조합에서 가로 넘침 및 JavaScript 예외 없음. 실제 검색·초기화·페이지 이동,
  본문 건너뛰기·검색 포커스·키보드 테마 전환·테마 저장·이미지 차단 메뉴·최근 탭을 확인했다.

## User Goal

- 사용자가 갤러리를 찾고, 게시글 목록을 훑고, 글을 읽은 뒤 댓글과 관련 글로 이어서 이동한다.
- 화면은 오래 읽어도 피로가 적고, 모바일에서도 주요 조작이 한눈에 들어와야 한다.

## Primary Path

1. 홈에서 갤러리 검색 또는 흥한 갤러리 목록을 본다.
2. 갤러리 행을 눌러 게시판 목록으로 이동한다.
3. 말머리, 전체/베스트 탭, 검색을 필요할 때만 조정한다.
4. 게시글 행을 눌러 읽기 화면으로 이동한다.
5. 본문, 댓글, 다른 게시글을 순서대로 읽고 목록으로 돌아간다.

## Secondary Paths

- 홈 검색어를 초기화하고 흥한 갤러리 순위로 돌아간다.
- 게시판에서 추천 보기와 전체 보기를 오간다.
- 게시판 하단 검색으로 제목, 내용, 글쓴이, 댓글 범위를 바꾼다.
- 최근 방문 화면에서 이전 갤러리로 바로 이동한다.
- 읽기 화면에서 관련 글 더보기를 눌러 다음 글을 이어 본다.
- 테마 전환 버튼으로 어두운 화면과 밝은 화면을 바꾼다.

## Initial Related List Contract

- 연속 더보기는 마지막으로 표시한 글 번호와 그 글의 원본 페이지를 함께 이어 간다.
  서버가 그린 초기 목록은 마지막 글 링크의 페이지를 사용하고, 이후에는 응답 행의
  페이지를 사용한다. 페이지가 없으면 직전 조회 페이지를 힌트로 유지한다.
  실패·빈 응답·중복 행만 있는 응답은 이어 읽을 위치를 바꾸지 않는다.

- 글에 진입하면 본문·댓글을 먼저 읽을 수 있고, 초기 다른 게시글 목록을 보기 위해
  더보기를 누를 필요가 없다. 기존 레이아웃과 검색·개념글·말머리 이동 조건을 유지한다.
- 본문 캐시는 갤러리·종류·글 번호별로 공유한다. 초기 목록은 같은 글이라도
  개념글 여부·검색 범위·검색어·말머리가 같은 경우에만 짧게 재사용한다.
  `source_page`는 기준 글을 찾는 힌트이며 목록 필터가 아니다.
- 원본 본문에서 함께 얻은 목록과 성공적으로 조회한 초기 목록은 해당 조건으로
  보존한다. 보존 기간은 본문 캐시 보존 기간 중 큰 값(기본 300초), 최대 512항목이며
  캐시 조회로 유효기간을 연장하지 않는다. 본문 캐시의 동시 요청 대기자는
  각자의 조건에 맞는 목록만 받는다.
- 유효한 초기 목록은 서버가 바로 표시한다. 목록이 없거나 만료됐다면 본문 응답을
  지연시키지 않고 브라우저가 한 번 자동 조회한다. 자동 조회와 버튼 클릭은 중복되지 않는다.
- 조회 중에는 로딩 상태와 `aria-busy`를 제공한다. 포커스를 임의로 이동하지 않으며,
  서버 조회는 12초, 브라우저 요청은 15초로 제한한다. 응답 지연·통신 실패 시
  기다림을 끝내고 수동으로 다시 시도할 수 있게 한다.
- 더보기는 현재 목록 다음 글을 추가한다. 중복 글을 제거하고 검색·개념글·말머리 및
  각 글의 페이지 힌트를 링크에 유지한다.
- `has_more: false`는 목록 끝이 확인됐을 때만 사용한다. 탐색 한도나 불확실한 페이지
  정보는 `null`로 표시하며, 원본 조회 실패·기준 글 탐색 실패는 재시도 가능한 오류로 구분한다.
  실패 때문에 이미 표시된 글을 제거하거나 버튼을 영구 비활성화하지 않는다.
- 빈 결과도 끝이 확인된 경우만 초기 목록으로 캐시한다. 목록 실패는 본문 실패가 아니다.
- 검증: 재방문·동시 조회·필터 변경·캐시 만료·PC 원본 대체로 목록이 없는 경우,
  자동 조회·추가 조회·시간 초과·재시도·확인된 목록 끝을 테스트한다.
  실제 브라우저에서 모바일/데스크톱, 키보드, 기존 행 유지, 가로 넘침을 확인한다.

## Screen States

| State | Required behavior |
|---|---|
| Loading | 게시글 행과 버튼은 active/pressed 상태를 즉시 보여준다. 관련 글 더보기는 버튼 자체가 loading 상태를 표시한다. |
| Empty | 홈, 게시판, 최근, 댓글, 관련 글은 각각 빈 행 문구를 유지한다. |
| Partial | 검색 실패나 흥한 갤러리 로딩 실패는 기존 오류 문구를 행 안에서 표시한다. |
| Success | 목록 행, 메타, 배지, 페이저가 같은 괘선 체계로 정렬된다. |
| Error | 서버 오류 문구는 기존 라우트 메시지를 유지하고 레이아웃이 깨지지 않는다. |
| Disabled | 이전 페이지가 없을 때 페이저는 비활성 스타일과 포인터 비활성을 가진다. |
| Selected | 활성 탭과 선택된 말머리는 `aria-current` 또는 `.active`와 밑줄로 표시한다. |
| Hover/Focus | 모든 링크, 버튼, 입력은 hover와 focus-visible이 시각적으로 보인다. |
| Mobile | 390px에서 검색 폼과 페이저가 줄바꿈되어 가로 스크롤이 없어야 한다. |
| Read | 긴 제목, 넓은 이미지, iframe, 테이블, 디시콘 댓글, 답글 들여쓰기가 컬럼 밖으로 넘치지 않아야 한다. |
| Related exhausted/error | 더 불러올 글이 없거나 실패했을 때 버튼 레이블과 비활성 상태가 명확해야 한다. |

## Information Hierarchy

- 첫 번째: 브랜드, 현재 위치, 전체/베스트/최근 탭.
- 두 번째: 검색 또는 갤러리/게시판 제목, 갱신 시각, 추천 전환.
- 세 번째: 목록 제목과 댓글 수.
- 네 번째: 작성자, 말머리, 시간, 추천 수 같은 메타.
- 필요할 때만: 페이지 이동, 검색 범위, 관련 글 더보기.

## Interaction Contract

- 브랜드: 홈으로 이동한다.
- 테마 버튼: 현재 테마를 반대로 바꾸고 로컬 저장소에 저장한다.
- 상단 탭: 전체, 베스트, 최근 방문 화면으로 이동한다.
- 홈 검색 입력: 갤러리명 또는 board id로 검색한다.
- 검색 초기화: 홈 기본 흥한 갤러리 목록으로 돌아간다.
- 게시글 행: 읽기 화면으로 이동하고 읽음 상태를 저장한다.
- 말머리 탭: 해당 분류의 1페이지로 이동한다.
- 게시판 검색: 선택된 범위와 검색어로 1페이지 검색 결과를 연다.
- 검색 해제: 검색 조건 없이 같은 게시판으로 돌아간다.
- 관련 글 더보기: JSON 엔드포인트에서 다음 관련 글을 추가한다.
- 관련 글 더보기 실패: 버튼을 다시 누를 수 있게 유지하고 실패 문구를 버튼 레이블에 표시한다.
- 맨 위로: 읽기 화면 상단으로 부드럽게 이동한다.

## Risk Checks

- 검색 폼이 모바일에서 버튼과 겹치지 않아야 한다.
- 제목이 길어도 댓글 수와 아이콘이 밀려 화면 밖으로 나가지 않아야 한다.
- 다크 모드에서 favicon 표식, 링크, 테두리 대비가 유지되어야 한다.
- 읽기 본문 이미지와 iframe이 컬럼 밖으로 넘치지 않아야 한다.
- 비활성 페이저가 링크처럼 보이면 안 된다.
- 장식성 UI가 정보 밀도를 낮추면 제거한다.
