# 댓글 없는 글의 원본 요청 절감 (2026-09-26)

## 원인과 변경

원본 모바일 본문에 댓글 수 `[0]`이 명시돼 있어도, 수집기가 댓글 수 미확인과 0을
같은 값으로 표현했다. 서비스는 내장 댓글이 비어 있으면 별도 조회를 시작했고,
확인한 실제 글에서는 본문 GET → 모바일 댓글 POST → PC 본문 GET → PC 댓글 POST가 발생했다.

- `Document.embedded_comment_total`의 기본값과 미확인 값은 `None`이다.
- 본문의 `reple_totalCnt`와 댓글 제목의 `ct`를 검사한다. 괄호·숫자·세 자리 쉼표 형식만
  허용하고, 누락·잘못된 값·서로 다른 개수는 미확인으로 처리한다.
- **0개가 명시되고 내장 댓글도 없을 때만** 추가 댓글 조회를 생략한다.
- 댓글이 있지만 개수가 0인 모순, 개수를 모르는 경우, 일부 댓글만 포함된 경우에는
  기존 댓글 조회와 모바일→PC 대체 경로를 유지한다.
- 댓글 0개도 기존 짧은 캐시 수명(기본 30초)을 따른다. 만료 후 댓글을 다시 조회하므로,
  저장된 본문을 재사용하더라도 새 댓글은 갱신된다. 캐시 수명과 오류 처리는 변경하지 않았다.

## 검증

- 전체 Python 테스트 793개, JavaScript 테스트 9개 통과.
- 새 테스트 25개: 명시적 0, 제목/숨은 필드, 쉼표, 누락/빈 값/음수/오류 값/상충하는 개수,
  내장 댓글과 개수 불일치, 완전한 내장 댓글에 대한 실제 document→service 호출 검증.
- 기존 댓글 캐시 회귀 테스트의 처음 댓글 0개 → 31초 후 새 댓글 사례 통과.
- 변경 전 실제 응답을 보관해 같은 응답으로 재생했을 때 요청은 **4회→1회**였고,
  본문 HTML SHA-256, 이미지 1개, 댓글 0개, 댓글 완전성 값이 모두 같았다.
- 로컬 Flask test client로 캐시 없는 일반 해외축구 글을 각각 5개씩 측정했다.
  변경 전 중앙값 **268.56ms**, 변경 후 **83.33ms**. 모두 HTTP 200, 호출 수는 글마다 4회→1회였다.
  동일 응답 재생은 결과/호출 수 검증이고, 이 시간은 별도의 실제 네트워크 측정이다.
  순차 소규모 표본이며 요청 시점·원본 내용·네트워크가 달라 운영 전체 개선율을 뜻하지 않는다.

## 범위

모바일/PC 선택 전략이나 PC 댓글 컨텍스트 캐시는 바꾸지 않았다. 원본 댓글 수 표시 자체가
틀린 경우까지 확인할 수는 없으며, 원본 본문을 읽은 시점의 명시적 개수를 신뢰한다.
문제가 확인되면 이 변경을 되돌려 기존 별도 댓글 조회를 복원할 수 있다.
