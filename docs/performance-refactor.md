# 동시 조회 최적화

## 문제와 변경

캐시가 비어 있거나 만료된 순간 같은 목록을 여러 요청이 읽으면, 기존에는
각 요청이 원본 서버에 별도로 접근했다. 게시글 읽기에는 이미 중복 조회 방지가
있었지만, 대기 요청이 50ms마다 완료 여부를 확인했다.

`app/services/singleflight.py`는 키별 소유자 선정, 완료 알림, 예외·취소 시 정리를
공통으로 처리한다. `concurrent.futures.Future`를 각 요청의 asyncio 루프에서 기다리므로
Flask의 공유 백그라운드 루프와 별도 스레드의 루프 모두 사용할 수 있다.
락은 등록·제거할 때만 잡고 원본 조회 중에는 잡지 않는다.

적용 범위는 `core.py`의 게시판 목록, 관련 글 페이지, 정확한 작성 시간,
게시글 읽기다. 게시판 결과와 페이지 정보를 복사하는 코드도 한곳으로 모았다.
HTTP 라우트, 응답 형식, 화면, 의존성, 원본 URL 선택과 파싱 규칙은 유지한다.

## 유지하는 동작

- 검색어·말머리·추천 여부·페이지·조회 제한 등 기존 캐시 키가 다른 요청은 독립적으로 조회한다.
- 기존 캐시가 있으면 즉시 반환한다. 새로고침 중에도 일반 요청과 쿨다운에 걸린
  새로고침 요청은 기존 캐시를 사용할 수 있다. 캐시가 없으면 진행 중인 조회를 공유한다.
- 명시적인 강제 새로고침과 일반 조회는 진행 중 조회를 구분한다. 서로 다른 빈 응답
  캐시 정책을 보존하기 위해 두 종류가 겹치면 각각 한 번씩 원본을 조회할 수 있다.
- 강제 새로고침 쿨다운과 빈 응답의 짧은 캐시 규칙을 유지한다. 일반 목록의 빈 응답은
  동시 요청에만 공유하고, 이후 요청은 다시 조회한다.
- TTL이 0이어도 진행 중인 작업은 공유한다. 완료된 결과를 다음 요청까지 보관하지는 않는다.
- 목록·분류·페이지 정보·시간·본문·댓글·이미지는 요청별 복사본으로 반환한다.
  읽기 소유자의 관련 글은 유지하고, 다른 탐색 문맥의 대기 요청과 캐시에는 공유하지 않는다.
- 읽기 조회의 50초 제한, 대기의 55초 제한, 기존 본문 재사용과 오류 처리는 유지한다.
  대기 요청을 취소하거나 대기 시간이 지나도 원본 조회와 다른 대기 요청은 취소되지 않는다.
- 조회 소유자가 실패하거나 취소되면 대기 요청에 실패를 알리고 등록을 제거한다.
  다음 요청은 재시도할 수 있다. 오류는 완료 값에 담아, 취소된 대기 요청에
  미회수 Future 예외가 남지 않도록 한다.

공유 범위는 **프로세스 내부**다. Gunicorn 워커가 여러 개면 워커마다 원본 조회가
한 번씩 발생할 수 있다. 캐시 TTL이나 네트워크 타임아웃을 늘리는 변경은 없다.

## 측정

2026-09-05, Python 3.12.13, 같은 환경에서 기준 커밋 `dba1f9c`와 변경 코드를 비교했다.
네트워크 대신 5ms 지연의 가짜 API를 사용하고, 매 회 캐시를 비운 뒤 동시 요청
32개를 10회 실행했다. 아래 숫자는 각 항목의 중앙값이다.

| 항목 | 변경 전 | 변경 후 |
|---|---:|---:|
| 게시판 목록 원본 조회 수 / 32요청 | 32회 | 1회 |
| 관련 글 페이지 원본 조회 수 / 32요청 | 32회 | 1회 |
| 작성 시간 원본 조회 수 / 32요청 | 32회 | 1회 |
| 게시글 읽기 원본 조회 수 / 32요청 | 1회 | 1회 |
| 읽기 데이터 준비 후 대기 요청 반환까지 | 46.105ms | 0.444ms |
| 읽기 동시 요청 묶음 완료 시간 | 52.689ms | 6.535ms |

목록 계열의 원본 조회 수는 이 조건에서 96.875% 감소했다. 외부 네트워크,
실제 HTML 파싱과 운영 부하는 포함하지 않으므로 운영 응답 속도의 보장값은 아니다.
목록의 묶음 완료 시간은 양쪽 모두 약 6.4ms로, 주요 이득은 중복 원본 요청 감소다.

```bash
.venv/bin/python scripts/benchmark_singleflight.py
# 같은 스크립트와 Python으로 다른 체크아웃을 비교한다.
.venv/bin/python scripts/benchmark_singleflight.py --repo /path/to/baseline
```

## 검증과 되돌리기

변경 전 Python 테스트 435개가 통과했다. 동시 조회 수, 캐시 비활성화, 빈 응답 재시도,
필터 간 병렬성, 새로고침 경쟁, 요청별 결과 격리, 실패·취소·대기 시간 초과,
서로 다른 스레드와 이벤트 루프의 완료 알림을 회귀 테스트로 검증했다.
전체 Python 테스트와 기존 JavaScript 상태 전이 테스트를 실행하고,
일반 조회와 강제 새로고침의 빈 응답 경쟁을 포함한 동시성·라우트·캐시 회귀도 확인했다.

```bash
make test PYTHON=.venv/bin/python
node --test tests/javascript/board_return_refresh.test.cjs
```

별도 데이터 마이그레이션이나 환경 변수 변경은 없다. 문제가 발생하면 이 변경의
커밋을 되돌리고 기존 배포 절차로 적용한다. 프로세스가 재시작되면 진행 중인 조회와
캐시는 초기화된다.
